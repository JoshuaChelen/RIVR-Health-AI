RIVR Health AI release-readiness completion audit

Objective:
- Achieve docs/release-readiness-agent-plan.txt.

Audit result:
- Not complete.
- Static validation, automated helper coverage, dependency hygiene, lint, typecheck, tests, worker build, Expo Doctor, and audit checks are passing.
- The remaining uncovered requirements are Apple Health permission behavior on a signed device/TestFlight build, real email-link auth recovery flows, positive-path media upload/capture/photo selection, and a final native seeded-data pass.
- The iOS simulator destination blocker was resolved by installing the iOS 26.4.1 Simulator runtime. The Expo dev launcher prompt was bypassed by building and installing a Release simulator app directly.
- Real mobile Timeline smoke tests now exist: the app authenticated into an existing QA account, opened Timeline, opened an event, entered edit mode, saved, and returned to read-only details without freezing. A later calibrated simulator run captured five consecutive no-op edit/save round-trips on the same event without freezing or crashing. Typed mobile search was also verified with a natural prompt, and the Timeline list Pre-Visit switch was toggled on without navigating or freezing, then toggled back off to preserve the QA account state.
- Native auth persistence was fixed by configuring Supabase auth to use React Native AsyncStorage. The rebuilt Release simulator app launched to Home from a QA session, was terminated, relaunched, and returned to Home instead of Login.
- Mobile keyboard handling was hardened: shared TextField inputs explicitly request the soft keyboard on focus, raw TextInput typing surfaces were patched with showSoftInputOnFocus, and Timeline event details now uses KeyboardAvoidingView while editing.
- Seeded legacy timeline render QA is now partially complete: temporary QA_LEGACY rows covered old/null/undated data shapes in the web/mobile-layout app, details, search, and edit/save. Those rows were cleaned up afterward.
- Destructive document removal was verified against a temporary QA_DELETE document row and cleaned up afterward.
- Pre-Visit edit-selection and Pre-Visit Note share variant were verified in the web app.
- Dark theme was scanned in the authenticated web app across Home, Timeline, Documents, Pre-Visit Note, Share Records, and AI Health Summary without crashes, obvious overlap, unreadable primary text, or broken navigation.
- Share Records now includes a native Share Link action in the generated-link modal. The action is implemented through React Native's native Share API and the Release iOS simulator build passes.
- Native Share Records generated a 3x5 Card secure link and the Open system share sheet action opened the real iOS share sheet. The share token is not documented.
- Native permission metadata was checked: app.json and the generated iOS Info.plist include the required usage strings for camera, photo library, microphone, Apple Health read, and Apple Health write prompts.
- The rebuilt Release app containing the native Share Link action was installed and launched on the iPhone 17 Pro simulator. It opened to Home with the persisted QA session.
- Native dark appearance was smoke-tested on the Release app Home screen and then through native deep links for Timeline, Documents, Pre-Visit Note, Share Records, AI Health Summary, AI Recommendations, Profile, Medical Profile, Story, and Apple Health.
- Native camera, photo-library, and microphone permission request paths were hardened with shared fallback helpers so denied or failed permission requests show stable app messages instead of becoming uncaught native errors.
- Native microphone, camera, and photo-library denial flows were exercised with Maestro against the iPhone 17 Pro simulator. Each denied prompt returned to a stable app fallback message.
- Apple Health startup was hardened so HealthKit permission constants are read lazily after native module availability checks rather than at module import time. The rebuilt Release app installed and launched to Home after this change.
- Apple Health error handling was hardened after native QA exposed an object-shaped HealthKit authorization failure. The screen now formats native errors without [object Object] and extracts the concise localized description.
