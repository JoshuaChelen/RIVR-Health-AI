2. Timeline Date And Age UX

Improve incident date and patient age display.

Requirements:
- Every timeline/incident card should show at minimum the incident year when available.
- If patient date of birth is available, calculate and display patient age at the time of the incident.
- If the full date is available and the event is <= 24 months old, show useful date detail in the main timeline.
- If the event is older than 24 months, show only the year in the main timeline view.
- Older events should reveal more specific date details only on the details screen.
- Clearly distinguish incident date from reported date when both are available.
- Add graceful fallback text if incident date, reported date, or DOB is missing.

Expected examples:
- "Left thumb injury occurred in 2016, when the patient was 42 years old."
- "Reported March 2024"
- "Incident year 2018, patient age 36"

Implement reusable helpers for:
- timeline date normalization
- date precision handling
- age-at-incident calculation
- display rules for <= 24 months vs older events
- fallback labels

3. Clinical Highlighting And Formatting

Improve timeline card and event details scanability.

Requirements:
- Improve visual hierarchy of timeline cards and event details.
- Highlight or bold key clinical elements where appropriate:
  - body part
  - side of body

  - major injury

  - medication
  - reported symptom
- Normalize common side/body abbreviations:

- Capitalize important clinical labels such as Thumb instead of thumb when used as a clinical label.
- Keep the UI clean, calm, and not cluttered.
- Make cards easier to scan for patients, doctors, and triage nurses.

Add reusable formatting helpers where appropriate.

4. Multimodal Search UX

Add or improve search across patient health cards and timeline data.

Users should be able to type natural prompts such as:
- "Show me all injuries from 2018."
- "Find my left thumb injury."
- "What medications was I taking after knee surgery?"
- "Show my timeline for shoulder pain."

Search should cover:
- dates
- injuries
- timeline events
- body parts
- medications
- diagnoses
- surgeries
- reported symptoms
- health card data where available

Requirements:
- Return results in a clear organized view.
- Do not break existing timeline/document functionality.
- If voice input is already supported or easy to add safely, add voice search using platform-supported input.
- If voice input is risky for release, implement typed search cleanly and put voice behind a feature flag or graceful fallback.
- Use an AI-answer search path for natural questions. The app must send the typed question to the worker/edge answer endpoint and must not pretend keyword matches are AI answers.
- Keep the timeline visible if AI search is unavailable, and show a clear fallback message instead of filtering the timeline locally.
